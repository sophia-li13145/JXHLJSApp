# PDA 右侧实体键扫码

## 设备配置

全部注册扫码页面均接入设备广播、直接填入 EditText 和模拟键盘输出。生产首页优先使用原机台输入框；没有扫码输入框的页面由 Activity 中不显示、不弹软键盘的原生接收控件承接文本。所有结果仍经过同一个当前页路由，不打开摄像头或相册扫码窗口。异常、返工上报和原料收货票签的拍照及图片压缩继续保留；原料收货票签额外提供扫码枪识别。

Newland 设备右侧实体键应映射为扫描触发键。广播模式可避免结果写入其他表单；全部扫码页面现已兼容原有文本输出模式，无需为了应用扫码修改设备输出配置。不要同时开启广播和键盘输出。指定目标包时使用 com.jxhljs.app。

Resources/Raw/appconfig.json：

~~~json
"rightKeyScanner": {
  "broadcastAction": "nlscan.action.SCANNER_RESULT",
  "dataKey": "SCAN_BARCODE1"
}
~~~

同时监听配置 Action、Newland 标准 Action、旧 lc 及持久化 hardwareScanner 配置中的自定义 Action。结果优先读取配置字段，再兼容 SCAN_BARCODE1、SCAN_BARCODE2、data；SCAN_STATE 非空且不为 ok 时丢弃。旧版本地配置保持有效，不覆盖服务器等用户配置。

应用收到的是解码结果，不能区分来自左键还是右键。右键启用及其他键禁用由设备配置决定。

## 页面与 UI

20 个扫码接收页面通过 IRightKeyScanService.Register 注册结果处理及业务可用条件；生产执行页的切换入口进入扫码页：

- 登录页：仅扫码登录标签接收。
- 生产角色首页、扫码上机页：机台绑定；生产执行页点击“切换机台”进入扫码上机页的切换模式，绑定成功后清理本地旧工单上下文和旧执行页导航历史，进入新机台的“选择工单开工”页；绑定失败留在扫码页重试。生产首页通过现有可见机台框补充接收设备文本，进入页面无需触屏或回车；静默 750ms 后只提交完整编号，后续扫描替换旧编号。点击机台框切换手动编辑，通过原确认/回车提交；失焦、离页或窗口切换后丢弃未完成文本。
- 上料、下料：按当前步骤处理机台码或物料码，保留酸洗机台复用。
- 完工：仅机台验证阶段接收，之后保留原确认流程。
- 异常、返工上报：识别物料，保留照片、表单和提交。
- 物料查询：进入等待状态，再次扫描刷新结果。
- 工序转运：识别后进入原转运流程。
- 来料质检详情、来料检验页、生产质检扫码、机台质检扫码：保留查询和检验流程。
- 新增巡检：先打开原新增面板；创建失败恢复面板，普通列表不创建。
- 质检详情：沿用工艺方案及已完成状态限制。
- 质检转码：原物料码→空白质检码；成功准备下一组，保留取消转码。
- 原料收货：并列提供“拍照识别”和“右侧键扫码识别”。拍照沿用压缩、上传附件和 /pda/rawMaterialReceiving/ocrIncoming（fileInfo、instockNo）；扫码将 instockNo 和二维码原文 scanContent 以 JSON POST 到 /pda/rawMaterialReceiving/scanIncoming。两种方式共用内容确认、扫码绑定、暂存及入库流程。拍照确认调用 saveOcrIncomingImage 并携带本次附件；扫码确认只保留页面票签内容，不调用图片保存接口，物料明细随后续暂存或入库提交。切换方式会清除上次附件，避免串用。确认票签后下一次侧键扫码用于绑定；更换扫码票签先点击“右侧键扫码识别”。识别失败仍可手动补录。拍照、录入、绑定、汇总及加载时不接收其他扫码。
- 包装：快捷入口进入等待状态；普通详情继续扫码，已完成详情不接收。
- 发货：保留物料复核及确认发货流程。

尽量保留原导航、卡片、表单、列表、尺寸与业务按钮，仅替换扫码文案和图标。点击原扫码区域只显示操作提示，不启动扫描引擎，也不是必要步骤。原有手动输入、确认、重扫、保存和提交保留。

## 接收链路

右侧实体键 → 设备扫描服务 → 广播接收器或统一原生文本接收控件 → RightKeyScanService → 当前页面业务方法。

广播接收器仅在 Activity 前台注册；文本接收控件只在当前页可扫码时准备焦点。页面异步加载、页内弹层等可用状态变化会自动同步接收焦点，无需重新进入页面。后台、失焦、错误弹窗、未注册或已离开页面、业务禁止状态均不处理。只分发给最上层页面；处理中不排队；页面/前后台切换前的排队结果丢弃；同页面同码 500ms 内过滤重复结果。去除边界控制字符，保留二维码内部 JSON 换行及 GS1 分隔符。日志只记录页面、Action 和长度。

## 真机验收

1. 保留设备现有输出模式，逐项进入全部 20 个扫码接收页面及生产执行页切换入口，不触屏直接按侧键。至少分别验证 Newland 广播、直接填入 EditText（无回车）和模拟键盘/回车模式。
2. 生产首页分别在广播、直接填入 EditText、模拟键盘模式下，不触屏、不回车扫描完整机台码（例如 PCAP_A），确认绑定一次并进入工单；返回后扫描另一编号应替换旧编号。手动点击输入框后通过确认或回车提交；绑定失败后应可再次侧键扫码。另验证员工码、物料码及带换行内容。
3. 验证上料/下料机台→物料、酸洗机台复用、转码两步流程。
4. 查询与快捷包装首次进入等待侧键，无摄像头弹窗或持续加载动画。
5. 新增巡检失败后直接按侧键重试；普通列表不创建单据。
6. 验证收货票签及确认弹层、只读质检及已完成包装状态。
7. 广播模式编辑重量、备注时扫码，结果不写入表单；文本模式不得抢占正在编辑的其他输入框。设备文本输出会写入当前编辑框，因此表单编辑期间需要独立扫码时应使用广播模式。不得重复请求或跳转。
8. 错误/系统弹窗、拍照、后台或页面离开时，底层页面不处理；返回可继续。
9. 拒绝相机权限仍可扫码；拍照单独申请权限。
10. 对照改造前界面检查提示换行、按钮文字及原表单，重点覆盖小屏 PDA。

日志依次确认 Right-key scanner listening、Right-key scan broadcast、Right-key scan accepted。无广播时核对设备输出模式、Action、字段及目标包。

生产首页文本输出排查：确认出现 Scan text input ready 且 Target=page-entry 日志。如果设备有解码提示音但无广播，检查机台框是否可接收设备文本，切勿仅以扫码提示音推断应用已收到结果。

## 切换机台后重新选单验收

生产执行页 → 点击“切换机台” → 扫描新机台 → 绑定成功 → 新机台“选择工单开工”页 → 用户选择工单并开工 → 新生产执行页。

- 使用从 Home 起始的导航路径，清理旧执行页和旧选单历史，避免返回键重新进入旧工单。
- 绑定成功才清理本地旧工单、执行记录引用、会话及酸洗机台确认状态。绑定失败或成功前取消不清理旧上下文。
- 机台编码通过 boundMachineCode 路由参数传入；首页绑定、普通扫码上机及切换机台统一使用此选单路径。
- 工单列表按返回的 deviceCode 匹配本次机台。后端只有旧机台或缺失设备编码的记录时显示空列表，不使用其他机台兜底。
- currentUserMachinesWorkOrder 结果按“工单号＋deviceCode”去重，保留同工单在不同机台的记录，防止筛选前丢掉新机台记录。
- 每次绑定跳转携带独立 refreshToken，同机台再次绑定也触发新查询。刷新请求与页面可见、导航就绪状态分开管理，兼容参数晚于 Appearing 到达及 Appearing 早于 NavigatedTo 的顺序；切换成功进入选单页自动查询；顶部“刷新”按钮和下拉刷新均查询当前机台最新工单，开工处理中不发起刷新。查询前清空旧列表；加载失败不可误点旧行；开工前再次验证当前列表成员及设备编码。
- 重新开工创建新 ProductionContext，使用本次绑定机台和新选工单，SessionId 重新生成，ExecutionId 不复用，IsPicklingMachineConfirmed 为 false。
- 开工防重复；离开选单页取消等待并拦截迟到的上下文更新。切换绑定后若导航失败，保留绑定结果，点击扫码区域或返回键重试进入选单页，不再次绑定。
- 选单页“重新扫码”进入实际扫码页；成功后重新创建目标机台列表。

本地上下文清理不代表后端旧工单已暂停或完工；没有自动调用旧工单暂停、完工接口。后端人员机台绑定、开工幂等及实际机台归属仍需联调验证。
